## Coverage and limits

The manifest exercises GPT and Hybrid configuration, known and tokenizer-derived
vocabulary, padding/no-padding, optimizer/DDP overrides, iteration/sample schedulers,
step and legacy batch schedules, data masking, local logging, checkpoint flag
translation/argument precedence, fresh training, actual checkpoint resume, TP/PP/DP,
and a deliberately conflicting CLI combination.

Builder cases use the real configuration and dataset builders, but a minimal
optimizer parameter-group fixture for scheduler derivation. Runtime cases use
actual training consumers. Checkpoint-argument cases check existing per-field
precedence, not a blanket assumption that checkpoint arguments override all CLI values.

Nine harness self-tests pass, including deliberately changed vocabulary/scheduler/DDP
values, missing captures/ranks, unsupported objects, and both-programs-failed handling.
Targeted isort/Black/ruff checks pass. Repository-wide pre-commit was also run in a
disposable clone; it reported pre-existing main formatting/style failures outside
these files. No unrelated formatter changes were retained.

This is configuration/input equivalence coverage, not a convergence or performance
gate. Short training/save/resume completion does not establish full numerical
equivalence. Logger/checkpoint captures are not an exhaustive audit of every consumer.
Neither PR7418 nor upstream main was modified. Raw logs and environment-specific
artifacts are not published; each local `report.json` contains source trees, per-file
harness hashes, fixture hashes, case outcomes, and every field difference.
